{% load i18n studio_tags %} {% comment %} Django's result table, with one addition: every cell carries its column header as a data-label attribute. Why: below 900px, responsive.css turns each into a stacked card, because a nine-column table cannot reflow and a horizontal scroll on a changelist is unusable -- you cannot see there is more to the right, so you do not know to scroll. As cards, the header row is redundant, and the only thing that can label each cell is the header text it replaces. Zipping `result` with `result_headers` is done in the template rather than by overriding admin_list.items_for_result, because items_for_result builds the labels and the bodies in two separate functions with no shared state, and forking the 100-line items_for_result to thread a string through would break on every Django upgrade. The two lists are parallel by construction -- both iterate cl.list_display in order -- so the zip is exact. {% endcomment %} {% if result_hidden_fields %}
